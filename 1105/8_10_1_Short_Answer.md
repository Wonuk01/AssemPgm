# Chapter 8 — 8.10.1 Short Answer (문제·정답·해설)

> 기준: 32비트 x86 MASM, Irvine32, 일반적인 STDCALL 스택 프레임. 원문 9문항.

## 1. 에필로그에 포함되는 명령은?
**정답:** 지역 변수 공간 해제(`mov esp, ebp` 또는 `leave`), 이전 EBP 복원(`pop ebp`), 복귀(`ret n`). `USES`로 보존한 레지스터가 있다면 복원도 필요하다.

**해설:** `leave`는 `mov esp,ebp` + `pop ebp`와 같다. STDCALL에서는 `ret n`으로 매개변수 공간도 정리한다. MASM의 PROC/LOCAL이 자동으로 에필로그를 생성할 수 있으므로 수동 코드와 중복하지 않는다.

## 2. C 함수의 32비트 정수 반환값은 어디에 저장되는가?
**정답:** `EAX` 레지스터.

## 3. STDCALL에서 호출 후 스택 정리는 누가 하는가?
**정답:** 피호출 프로시저(callee)가 `ret n`으로 매개변수 바이트 수만큼 ESP를 증가시킨다. 예: DWORD 인수 3개면 `ret 12`.

## 4. LEA가 OFFSET보다 강력한 이유는?
**정답:** `LEA`는 실행 중 레지스터와 인덱스·배율·변위를 조합한 유효 주소를 계산할 수 있다. `OFFSET`은 어셈블 시점에 결정되는 심볼의 오프셋을 구한다.

```asm
lea esi, [ebx + ecx*4 + 8]  ; 실행 시 계산
mov esi, OFFSET array       ; 심볼의 고정 오프셋
```

## 5. 8.2.3 C++ 예제에서 int 변수의 스택 크기는?
**정답:** 4바이트(32비트 환경의 일반적인 `int`).

## 6. C 호출 규약(cdecl)의 STDCALL 대비 장점은?
**정답:** 호출자가 스택을 정리하므로 가변 인수 함수(`printf` 등)를 지원하기 쉽다. 호출마다 인수 개수가 달라도 호출자가 정확한 크기를 정리한다.

## 7. PROC 매개변수는 반드시 한 줄에 나열해야 하는가? (T/F)
**정답:** False. MASM에서는 줄 연속 표시 등을 사용해 여러 줄로 작성할 수 있다.

## 8. BYTE 배열 주소를 WORD 배열 포인터 매개변수로 넘기면 항상 어셈블 오류인가? (T/F)
**정답:** False. 주소를 DWORD 포인터 값 등으로 전달하면 어셈블러가 가리키는 실제 배열 원소 타입을 항상 검증하지 못한다. 선언·인수 표현식에 따라 정적 타입 검사가 발생할 수 있으므로 '항상 오류'는 아니다.

## 9. 참조 매개변수에 즉시값을 넘기면 일반 보호 예외가 발생할 수 있는가? (T/F)
**정답:** True(발생 가능). 주소로 해석된 값이 유효하지 않거나 접근 권한이 없는 메모리를 가리키면 접근 위반/보호 예외가 발생할 수 있다. 단, 타입 검사가 먼저 어셈블 오류를 낼 수도 있다.

## 암기 핵심
- 반환값 `EAX` / 스택 프레임 기준 `EBP` / 스택 꼭대기 `ESP`
- `STDCALL`: callee 정리 / `cdecl`: caller 정리
- `LEA`: 실행 시 주소 계산 / `OFFSET`: 어셈블 시 주소 상수
- `LOCAL`: 지역 변수 / `PROTO`: 선언 / `INVOKE`: 인수 전달 및 호출
