## 문제별 정답 및 해설

### 1. 32비트 모드에서 ESP 외에 스택의 변수를 가리키는 레지스터는?

**정답: EBP (Extended Base Pointer)**

-   `ESP`는 현재 스택의 꼭대기(top)를 가리킵니다.
-   `EBP`는 함수의 스택 프레임을 기준으로 매개변수와 지역 변수를
    참조하는 데 전통적으로 사용됩니다.

------------------------------------------------------------------------

### 2. CPU 상태 플래그를 최소 4개 쓰시오.

**정답 예시: CF, ZF, SF, OF**

-   **CF (Carry Flag)**: 부호 없는 연산에서 자리올림/자리빌림 발생
-   **ZF (Zero Flag)**: 결과가 0일 때 설정
-   **SF (Sign Flag)**: 결과가 음수일 때 설정
-   **OF (Overflow Flag)**: 부호 있는 연산에서 오버플로 발생

추가로 `PF (Parity Flag)`, `AF (Auxiliary Carry Flag)` 등이 있습니다.

------------------------------------------------------------------------

### 3. unsigned 산술 연산 결과가 목적지에 들어가기 너무 클 때 설정되는 플래그는?

**정답: CF (Carry Flag)**

`CF`는 주로 **부호 없는 정수 연산의 범위 초과**를 확인할 때 사용합니다.

------------------------------------------------------------------------

### 4. signed 산술 연산 결과가 너무 크거나 작아서 목적지에 들어가지 못할 때 설정되는 플래그는?

**정답: OF (Overflow Flag)**

`OF`는 **부호 있는 정수 연산의 범위 초과**를 나타냅니다.

> 암기: **unsigned → CF / signed → OF**

------------------------------------------------------------------------

### 5. 32비트 레지스터 operand에서 REX prefix를 사용하면 R8D를 사용할 수 있다.

**정답: True**

x86-64에서 REX prefix를 이용하면 확장된 범용 레지스터 `R8~R15`에 접근할
수 있으며, `R8D`는 `R8`의 하위 32비트입니다.

------------------------------------------------------------------------

### 6. 산술 또는 논리 연산 결과가 음수일 때 설정되는 플래그는?

**정답: SF (Sign Flag)**

결과의 최상위 비트(MSB)를 반영하여 부호 있는 결과가 음수인지 판단하는 데
사용됩니다.

------------------------------------------------------------------------

### 7. CPU에서 부동소수점 연산을 담당하는 부분은?

**정답: FPU (Floating-Point Unit)**

FPU는 실수와 같은 **부동소수점 수의 산술 연산**을 담당합니다.

------------------------------------------------------------------------

### 8. 32비트 프로세서에서 각 부동소수점 데이터 레지스터의 크기는?

**정답: 80 bits**

전통적인 x87 FPU는 `ST(0) ~ ST(7)`의 8개 데이터 레지스터를 가지며 각각
**80비트 확장 정밀도(extended precision)** 형식을 사용합니다.

------------------------------------------------------------------------

### 9. x86-64 명령어 집합은 x86 명령어 집합과 하위 호환된다.

**정답: True**

x86-64는 기존 x86 소프트웨어와의 호환성을 고려하여 설계되었습니다.

------------------------------------------------------------------------

### 10. 현재 64비트 칩 구현에서는 주소 지정에 64비트 전체를 사용한다.

**정답: False**

64비트 레지스터를 사용하더라도 실제 구현에서 **64비트 주소 공간 전체가
물리적/가상 주소 지정에 사용되는 것은 아닙니다.**

------------------------------------------------------------------------

### 11. Itanium 명령어 집합은 x86 명령어 집합과 완전히 다르다.

**정답: True**

Itanium의 **IA-64** 아키텍처는 x86/x86-64와 다른 명령어 집합 구조를
사용합니다.

------------------------------------------------------------------------

### 12. SRAM은 일반적으로 DRAM보다 저렴하다.

**정답: False**

일반적으로 **SRAM이 DRAM보다 빠르지만 더 비쌉니다.**

-   SRAM → 빠름, 비쌈 → 주로 CPU Cache
-   DRAM → 상대적으로 느림, 저렴 → 주로 Main Memory

------------------------------------------------------------------------

### 13. REX prefix를 사용할 때 64비트 RDI 레지스터를 사용할 수 있다.

**정답: True**

64비트 모드에서 `RDI`는 사용 가능한 64비트 범용 레지스터입니다.

------------------------------------------------------------------------

### 14. native 64-bit mode에서 16-bit real mode는 사용할 수 있지만 virtual-8086 mode는 사용할 수 없다.

**정답: False**

64비트 **long mode**에서는 virtual-8086 mode가 지원되지 않으며, 16비트
**real mode 자체도 long mode의 실행 서브모드가 아닙니다.** 따라서 문장
전체는 False입니다.

------------------------------------------------------------------------

### 15. x86-64 프로세서는 x86 프로세서보다 일반 목적 레지스터가 4개 더 많다.

**정답: False**

기존 x86에는 주요 범용 레지스터가 8개였고, x86-64에서는 `R8~R15`가
추가되어 **8개가 더 추가**, 총 16개가 됩니다.

------------------------------------------------------------------------

### 16. 64비트 Microsoft Windows는 virtual-8086 mode를 지원하지 않는다.

**정답: True**

64비트 Windows 환경에서는 virtual-8086 mode를 사용할 수 없습니다.

------------------------------------------------------------------------

### 17. DRAM은 자외선을 이용해야만 지울 수 있다.

**정답: False**

DRAM은 전하를 저장하여 데이터를 유지하고 주기적인 **refresh**가
필요합니다. 자외선으로 데이터를 지우는 것은 전통적인 **EPROM**과 관련된
특징입니다.

------------------------------------------------------------------------

### 18. 64비트 모드에서 최대 8개의 floating-point register를 사용할 수 있다.

**정답: True**

전통적인 **x87 FPU 관점**에서는 `ST(0) ~ ST(7)`까지 총 8개의 부동소수점
데이터 레지스터를 사용합니다.

※ 현대 x86-64에는 별도로 XMM/YMM/ZMM 같은 SIMD 레지스터도 존재하지만, 이
문제는 교재의 x87 floating-point register 문맥을 기준으로 합니다.

------------------------------------------------------------------------

### 19. 버스(bus)는 메인보드에 직접 위치하지 않고 양 끝이 메인보드에 연결된 플라스틱 케이블이다.

**정답: False**

버스는 CPU, 메모리, I/O 장치 사이에서 **데이터, 주소, 제어 신호를
전달하는 통신 경로**를 의미합니다. 반드시 특정 형태의 플라스틱 케이블을
뜻하지 않습니다.

------------------------------------------------------------------------

### 20. CMOS RAM은 SRAM과 같으므로 추가 전력이나 refresh 없이 값을 유지한다.

**정답: False**

SRAM은 refresh가 필요하지 않지만 **전원이 공급되는 동안에만** 데이터를
유지하는 휘발성 메모리입니다. CMOS 기반 설정 저장 영역 역시 전원 유지가
필요하여 전통적인 PC에서는 배터리를 사용해 내용을 보존합니다.

------------------------------------------------------------------------

### 21. PCI 커넥터는 그래픽 카드와 사운드 카드에 사용된다.

**정답: True**

PCI 계열 확장 슬롯은 그래픽, 사운드, 네트워크 등의 확장 카드 연결에
사용되어 왔습니다. 현대 그래픽 카드는 주로 **PCI Express (PCIe)**를
사용합니다.

------------------------------------------------------------------------

### 22. 8259A는 하드웨어 장치에서 발생하는 외부 인터럽트를 처리하는 컨트롤러이다.

**정답: True**

**8259A PIC (Programmable Interrupt Controller)**는 여러 하드웨어
인터럽트 요청을 받아 CPU에 전달하고 우선순위를 관리합니다.

------------------------------------------------------------------------

### 23. PCI는 Programmable Component Interface의 약자이다.

**정답: False**

정확한 의미는:

**PCI = Peripheral Component Interconnect**

------------------------------------------------------------------------

### 24. VRAM은 Virtual Random Access Memory의 약자이다.

**정답: False**

정확한 의미는:

**VRAM = Video Random Access Memory**

그래픽 데이터를 저장하기 위한 비디오 메모리를 의미합니다.

------------------------------------------------------------------------

### 25. 어셈블리 언어 프로그램은 어느 수준에서 I/O를 조작할 수 있는가?

**정답: 여러 수준에서 조작할 수 있습니다.**

대표적으로:

1.  **고수준 OS 함수/API 호출**
2.  **BIOS 또는 시스템 서비스 사용**
3.  **하드웨어 장치의 I/O 포트에 직접 접근**

즉, 어셈블리 언어는 운영체제가 제공하는 서비스를 사용할 수도 있고,
허용되는 환경에서는 더 낮은 하드웨어 수준까지 접근할 수도 있습니다.

------------------------------------------------------------------------

### 26. 게임 프로그램이 사운드 출력을 사운드 카드의 하드웨어 포트로 직접 보내는 경우가 많은 이유는?

**정답: 성능을 높이고 출력 지연을 줄이기 위해서입니다.**

게임은 사용자 입력과 화면 변화에 맞추어 소리가 빠르게 재생되어야 합니다.
중간 소프트웨어 계층을 줄이고 하드웨어를 직접 제어하면, 특히 전통적인
저수준 환경에서는:

-   사운드 출력의 **응답 속도 향상**
-   **지연(latency) 감소**
-   세밀한 하드웨어 제어
-   게임의 실시간 처리 성능 향상

등의 이점을 얻을 수 있습니다.

> 현대 운영체제에서는 보안과 안정성 때문에 일반 응용 프로그램이 하드웨어
> 포트를 직접 제어하기보다 드라이버와 오디오 API를 사용하는 것이
> 일반적입니다.

## 시험 직전 암기 포인트

-   **EBP** → 스택 프레임 기준점
-   **ESP** → 스택 꼭대기
-   **CF** → unsigned overflow
-   **OF** → signed overflow
-   **SF** → negative result
-   **ZF** → zero result
-   **FPU** → floating-point 연산
-   **x87** → 80-bit × 8 registers
-   **x86-64** → 기존 8개 + R8\~R15 = 총 16개 범용 레지스터
-   **SRAM** → 빠르고 비쌈, Cache
-   **DRAM** → 저렴하고 refresh 필요, Main Memory
-   **8259A** → Programmable Interrupt Controller
-   **PCI** → Peripheral Component Interconnect
-   **VRAM** → Video Random Access Memory
